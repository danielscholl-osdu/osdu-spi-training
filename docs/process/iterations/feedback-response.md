## Decisions where the review needed qualification

- A two-hour schema load is not established as normal by its 150-minute deadline. Timing labels distinguish observations, overlapping phases, and timeouts. The prototype does not invent per-phase elapsed times or price estimates.
- The audience knows OSDU but is explicitly new to SPI. The introduction bridges familiar APIs and expands Service Provider Interface once.
- A no-access caller is not a universal 401 probe. Partition's tenant app-only behavior differs from entitlements-protected APIs; the caller panel states this limit.
- Profiles select workloads, not a smaller Azure resource estate. The illustration stays on core; a profile toggle would add controls before it adds a useful learning distinction.
- Ordinary teardown and purge have different identity and grant behavior. This iteration teaches ordinary teardown; the source notes preserve the purge qualification for later narration.

## Documentation drift

The review correctly identified a mismatch between `osdu-spi/doc/src/concepts.md` and ADR-038: the concepts diagram depicts upstream Azure code flowing through ongoing synchronization, while ADR-038 makes Azure provider and test source fork-owned after an initial seed. The correction is tracked in [issue #193](https://github.com/Azure/osdu-spi/issues/193) and [draft PR #195](https://github.com/Azure/osdu-spi/pull/195), whose description follows the repository’s What / Why now / Notes for review format. The PR changes only the concepts page.

Documentation browser checks also reproduced a separate Mermaid initialization failure on the unchanged page. The revised diagram source parses and renders independently, while [issue #194](https://github.com/Azure/osdu-spi/issues/194) records the existing page-rendering defect. No experimental renderer changes are included in the PR.
