# Fieldnote 104 · The line

**Status: published.** Level 100, the fourth foundation episode. Its companion page is `chapters['the-line']`, and its cut-from record is in `src/content/videos.js`.

**Who is watching:** anyone taking the course, straight after 103. **What they should believe after it:** a service fork owns a few of its paths, its workflows come from one template, and the community's code is regenerated from upstream every day; a change reaches a running service through six stations that are the same in every fork; and every eligible commit gets an image and a turn in a running stack before any release exists, so a release only tags an image that is already there.

**The scene:** each beat is a concept scene drawn in vector motion, in the site's colors and fonts, with something always moving. No scene shows the site's interface, a map drawing, GitHub footage, or a command. Everything stays at level 100: one fork, one line, one stack drawn as a card.

**Made from:** boards in Fieldnotes 04 and 05, simplified. Fieldnote 04's ownership grid becomes one fork's tree in three tones (beat 1); Fieldnote 05's lanes turn into one line of stations (beat 2); its image chip and the stack's service slot carry beat 3. All narration is new. Branch names, labels, the tracking issue, the image lock, and footage stay out: P203 and P204 read the fork by its branches and its day, S206 follows a pull request's checks, and P205 opens the lane.

## Word list the narration must keep

- No fork count. "Every service fork" names them all; the count changes as forks are added. (Thirteen in the stack's roster on 23 October 2026.)
- Not every change visits every station: a fork's own change joins at main. Say so once, in beat 2, and keep the recall to "every fork has the same six stations", never "every change rides all six".
- Sync proposes; it does not merge. Who approves where is 105's, so the narration names no approval.
- The lane is a station, drawn as a loop under Cascade and Main and spoken after release as the one "beside them", because it runs on the pushes to the workspace and to main and on the fork's own pull requests, all before any release. Borrow, prove, and restore are P205's; this episode says only "a turn in a running stack".
- "Eligible" stays in the narration. Which commits are eligible is S206's.
- A release tags an image that already exists and rebuilds nothing. It does not say which commit's image, because the release commit gets its own image.
- "Main's image is the one a stack runs by default" is as far as the episode goes; when a stack moves to it is S204's.
- The three owners: the fork (orange, its few paths), the template (its workflows), and the community (the rest). Orange appears only on the fork's own paths and the fork's own change.
- No branch names, labels, tracking issue, image lock, version numbers, or commands on screen.
- The provider lives in the fork, in the present tense. No upstream history, removal, or dates.
