## The companion page

The page `ready-not-loaded`, rewritten from this storyboard:

- Question: "What does a new environment hold, and does ingestion work?"
- Claim 1, "A Deployable environment holds schemas and no records": "Bring-up registers the schemas and writes no records; reference data, from the community's data definitions, is loaded by nothing until you run spi load, and spi load refuses to start until the environment is Deployable."
- Claim 2, "Loaded means Storage accepted the records, not that search finds them": "spi load creates one Job per partition that writes the reference data to Storage; complete means Storage accepted the records, and the indexer may still be working."
- Claim 3, "Ingestion writes on behalf of whoever started it": "Deployable does not wait for the DAGs to register, so prove ingestion: a run started with your own token writes on behalf of you, and the stored record's createUser is you, not the platform."
- Example: _spi test dags, as me_, `spi test dags --as me --report`, four hops: Preflight; Echo, then an ingest; The scheduler task; Read back.
- Easy mistake: "It's Deployable, so the data is there." (`deployable-means-loaded`, checked with `spi load --status`).
- How Ready and Deployable are computed is P201's, and the catalog, the registration Job and the on-behalf-of mechanism are P305's and S303's; the page names them only in the drawer. Lesson 11 keeps its own page until S303 replaces it.
