## Word list the narration must keep

- One run borrows one service's slot. The board never shows a whole environment being replaced.
- The run writes the lock; Flux deploys. The workflow never applies a Deployment itself.
- No test result counts until Verify has read the candidate digest on the pod.
- Reset with the run's id writes nothing when a newer run owns the pin, and exits 2, which the lane treats as success. A cancelled run or a lost runner strands its pin; that is lesson 06's depth and stays out of the narration.
- The stack and the fork share no code. Facts come from `spi status --json` and `spi info --json`; needs come from `.spi/service.yaml`.
- The partition fork adopted the lane in September 2026, but the run shown is illustrative: no digest, run id, PR number, or log line from a real run appears.
- The cache fallback was proved by unit tests in the build; the suites prove the API on the pinned pod. Neither is said to prove the other.
