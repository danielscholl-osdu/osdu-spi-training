# Fieldnote 05 · A day in the fork

**Status: in production.** Cut from lesson 05 (`chapters['fork-day']`). Aim for about 3 minutes.

**Who is watching:** an engineer who has seen the fork's three branches in Fieldnote 04. **What they should believe after it:** upstream arrives as a generated tree through a reviewed PR, never as a merge someone runs; the tracking issue's labels are the state of the day; and every eligible commit gets an image digest and a turn in the stack before any release exists, so a release only tags an image that is already there.

**The form is mixed: boards and GitHub footage.** Footage is captured from the public pages of `Azure/osdu-spi-partition` on the day of the cut: the Sync Upstream runs at midnight, a sync PR into `fork_upstream`, a tracking issue and its labels, and the container package's tags. Boards follow the lesson's figure, "The branches, in time", as five moments. Lesson 05's outcomes are plain sentences, so its chapters are titled with the sentences.

**The scene:** the three branch columns from Fieldnote 04 turn on their side into three lanes on a time axis, midnight at the left. Upstream sits above the lanes, outside them. The stack appears only at the fourth moment. Fork-owned changes are orange. One generated illustration carries the recall.

- Times on the axis are the workflows' scheduled triggers, not measurements. Only the midnight sync is named.
- Upstream is never merged as text. The only merges are the cascade's into `fork_integration` and the reviewed PRs.
- The cascade order is `main` first, then `fork_upstream`.
- Validation pushes a digest for every eligible commit; "eligible" stays in the narration.
- The release is optional and tags an image that already exists. Release Please opens the version PR; the episode does not explain Release Please further.
- Template sync, the cascade monitor, and Settings Apply run on their own clocks and stay off screen.
- The cache fix and its unit tests are real; the acceptance run is illustrative. Say both, once.
