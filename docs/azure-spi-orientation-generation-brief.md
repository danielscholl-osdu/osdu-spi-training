# Orientation conversation brief

Use **azure-spi-orientation.pdf** as the only selected source for this conversation. Keep the three original PDFs as deeper reference material, outside this generation's selected context. The source document contains the subject matter; this brief is the separate instruction for shaping the conversation.

Suggested generation prompt:

> Create a thoughtful orientation conversation for senior engineers who already know OSDU APIs and data partitions but are new to Azure SPI. Use only the attached orientation source. Follow its order: familiar contract and new responsibility; repositories and artifacts; the running stack; creation and readiness; the partition provider and cache fallback; fork ownership; image and evidence; borrow, prove, restore; identity; the next learning steps.
>
> Establish the whole system in the first three minutes. Distinguish the interface, the stack, and the engineering system in ordinary language, then connect them using the partition lookup for opendes in dev1. Keep returning to that same lookup and its cache fallback fix. Explain why the boundaries exist and what changes at each handoff. Prefer causal questions and concrete consequences to catalogs of features.
>
> Let the conversation develop the reasoning rather than read the document aloud. One speaker may voice a reasonable misunderstanding; the other should resolve it using the source and the running example. Give listeners a short pause or recap when changing from environment to code, from code to the fork, and from the fork back to the stack. Close by carrying the same request and fix around the complete loop.
>
> Aim for roughly fifteen to eighteen minutes if the available duration control permits. The exact duration matters less than a coherent opening and a complete round trip. Preserve the distinction between the real cache fix and the illustrative acceptance run. Preserve the limits of readiness, test evidence, shared access, and ownership-aware restoration. State supported behavior with its condition in the same sentence. Keep the tone calm, precise, and curious.
>
> The detailed schedules, Git plumbing, configuration recipes, and other mechanisms in the original reference books are outside this orientation. Do not introduce them from general knowledge. Avoid service counts, provisioning promises, production claims, and security superlatives. Use the names and relationships in the supplied source.

## Review the generated conversation before using it

This is editorial review of an artifact, not a learner exercise or completion gate. Constrained input reduces the opportunity for drift; it cannot establish the factual accuracy of a new recording.

- By the first three-minute break, the listener should have heard what the three meanings refer to and how a service repository, image, and stack connect. A long explanation of why OSDU exists does not serve this audience's immediate need.
- The partition lookup must reach the cache and common Storage tables. The recording should distinguish that configuration lookup from other services using Cosmos DB, blobs, or events.
- The cache fallback should remain real history; the later acceptance run should remain an illustration of the newer template's lane.
- Creation, reconciliation, verified image identity, test reports, and restoration should remain separate observations.
- Shared deployment access must not become a claim of per-service isolation or of harmless compromised images. Middleware credentials must not disappear from the explanation.
- The restoration condition should be spoken where restoration is introduced: restore only while the run owns the pin, and recognize that a lost runner can leave recovery work.

For site integration, make the opening three-minute cue a complete conceptual introduction with a natural ending. Cut later cues at sentence boundaries. Each cue should explain the relationship visible in its destination view, stop at its section boundary, and retain a transcript. Keep the full conversation as optional listening.

Preserve the original recordings and PDFs. Review the new recording against the source before changing the site's primary orientation selection.
