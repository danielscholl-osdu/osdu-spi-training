CLI writes after Flux activation; every spi up repeats it.
Delete a chart Secret and reconciliation does not rotate it: the next spi up copies the same seed password back.
Delete the seed and a later spi up can mint new passwords while the running databases still hold the old ones.
Rotation is not automated. Nothing coordinates seed, databases, Secrets, mirror, consumers. Planned maintenance, not a pod restart.

Next spi up adopts the identities, reuses the suffix, recovers the vault, mints new middleware passwords, rewrites the mirror. The seed is gone.
Full removal
Opt in
spi down --purge
1 · Inventory external role assignments from the retained principal IDs, subscription-wide.
2 · Remove and confirm the stack-owned DNS Zone Contributor grant; the zone is never a target.
3 · Delete the group and its identities; wait for Azure to report it gone, same 45-minute deadline.
Stop condition. An unknown grant, a discovery failure, or an unconfirmed removal halts purge with the group and identities standing.

Verdict
Azure access survives a rebuild because it has nothing to lose; the middleware does not.
Identities and tags ride the group through spi down; the seed dies with the cluster, so a rebuild mints fresh passwords. Only --purge takes the ground.
