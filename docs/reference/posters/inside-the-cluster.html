The ladder · dependsOn plus wait: true, layer by layer
Layer 1 · foundation
Operators, in parallel
cert-manager, ECK, CloudNativePG, Helm sources. trust-manager waits on cert-manager.
Layers 2 to 3 · platform
Middleware on its operator
Elasticsearch on ECK, PostgreSQL on CNPG, Redis on cert-manager and Helm sources. Airflow waits on PostgreSQL.
Layers 4 to 6 · osdu
Bootstrap, services, Jobs
CA Bundles and Redis DestinationRule, then core services, then init, schema load, legal and members Jobs, then reference APIs.
Floor · layers 0a and 0b · spi-namespaces then NodePools · every rung stands on these
Gates
Later layers start only when earlier ones report Ready, and Ready means workload health, not manifest applied.
Timeouts per layer: 10 to 15 min middleware, 30 min OSDU layers. Schema-load Job deadline 150 min is a ceiling, not a duration (its layer allows 155).
Non-gating
Legal-tag and members seeding are leaves. A failed seed stays visible without holding back Ready.
Reference APIs wait on core services and schema load only. Fork RBAC sits outside the chain.
Two switches · fetching is not reconciling
Switch 1 · Git fetching
Suspended after deploy
Source polling, off by default
spi up ends by setting spec.suspend: true on the osdu-spi-stack-system GitRepository. No new commits arrive until spi reconcile --resume. Resumed, it polls every ten minutes.
Switch 2 · Reconciliation
Always on
Kustomizations and HelmReleases keep working
They apply the cached revision and live inputs: osdu-image-lock substituted at reconcile, upstream Helm repositories, operators. spi reconcile --refresh-images rolls services without touching Git.
Suspension is not a snapshot.
Live ConfigMaps can change, external charts and controllers keep their own cadence. Only the Git fetch is pinned.
Diagnosis · one command per layer, then walk dependsOn upstream
The graph · osdu-flux
kubectl get kustomizations -n osdu-flux
flux get helmreleases -n osdu-flux
A downstream error names only its direct dependency. Follow it to the first unhealthy Kustomization.
Workloads · by namespace
kubectl get pods -n foundation
kubectl get pods -n platform
kubectl get jobs -n osdu
HelmRelease objects and Helm history stay in osdu-flux, not here.
Stalled · RetriesExceeded
Ready=False, Stalled=True. Retries spent, helm-controller stopped, dependents at DependencyNotReady, pods possibly healthy.
Re-applying the unchanged manifest does nothing. spi reconcile resets it for one forced attempt. A terminal stall (bad chart, bad CEL) needs a real change.
Verdict
Read the namespace that owns the failure, not the one that reports it.
Flux state in osdu-flux, workload state in foundation, platform, osdu. The last blocked service is rarely the cause.
